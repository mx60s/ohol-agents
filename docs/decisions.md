# Study and build decisions

Running log of design decisions, newest last. Each should be revisited if its "revisit" note applies.

- **2026-11-16 · Traits are mock for now.** Each life gets a trait vector (default Big Five via `TRAIT_DIMS`), Eve ~ N(0,1) clipped ±2.5, child = mother + N(0, 0.15). Nothing uses them to steer behaviour yet. Labelled MOCK on the site. *Revisit:* the trait set will change to non-normative traits; hair colour mapping (`hairColorForTraits`) must change with it.
- **2026-11-16 · Appearance.** Hair colour from personality (elders fade to a silvery pastel, grey capped at 60%); each lineage gets a distinct hairstyle + eyes/mouth; skin is always the server's (babies always take the mother's race: `childSameRaceLikelihood=1.0` pinned). Players can't choose their look. Genitals and pubic hair are never drawn.
- **2026-11-16 · Always-on, no spend cap by default.** `CONTINUOUS=1`, `MAX_COST_USD` off in continuous mode; caps available as opt-in.
- **2026-11-17 · New-player food bonus ON, as a declared condition.** Stock OHOL gives new players +18 s per food pip (off on our server because it depends on the stats server). Turned on to match what human newcomers get; listed under Interventions.
- **2026-11-17 · No cross-life memory.** Each life starts fresh. Knowledge passes only in-game (speech, objects, the home marker), so inheritance isn't confounded by an agent slot carrying memories into an unrelated family.
- **2026-11-17 · `craft <item>` macro: ON for now, TEMPORARY.** Walks the recipe graph (comparable to a human with the wiki open), listed under Interventions. **The user wants to strongly consider removing it later** — revisit before the main study runs, and treat runs with and without it as different conditions.
- **2026-11-17 · Starting setup: few Eves, staggered logins.** ~2-4 Eves; other agents join over time and are born into families. (Forcing 20 simultaneous Eves would scatter one-woman camps ~50 tiles apart.)
- **2026-11-17 · Statistics: the effective n is the number of families.** All trait tests use family-aware permutation; ~80 founding families is enough for one pre-registered moderate effect, not an all-traits FDR screen (~160 needed). Prefer more independent founders over longer runs; pre-register 1-2 primary tests.
- **2026-11-17 · Scale the whole game clock to model reaction time.** One `TIME_SCALE` knob slows every game timer uniformly (aging, food and heat drain, decay and regrowth, movement), so all in-game ratios are preserved. Slowing only aging (an earlier attempt) just made agents starve faster. Declared intervention. Cost per generation scales with the factor.
- **2026-11-17 · Talk to models in turns, not seconds.** Every duration in the prompt and observation is expressed in decision turns ("a newborn can be set down for 1 turn").
- **2026-11-17 · Fixed decision cadence (`DECISION_CYCLE_MS`, ~8 s) in every condition,** so faster models don't act more often in game time (a confound found by the cost model).
- **2026-11-17 · Assume the model is competent.** Remove every harness barrier (parsing, action reliability, hearing, information, time to think) before blaming the model; don't script play.
- **2026-11-17 · Fixed decision cadence.** `DECISION_CYCLE_MS` (default 8000, start-to-start) for every model, so latency doesn't set how often an agent acts in game time. Calibration (fast inference) will pick the final value, likely 3-4 s. *Revisit:* after calibration.
- **2026-11-17 · Food bonus implemented as a fixed bonus.** `mtsNewPlayerFoodBonus=1` gives every life the full +18 s/pip (no lifetime decay), the same for every life. Configurable; may be dropped if `TIME_SCALE` is used.
- **2026-11-17 · LLM outage = paused run, invalid lives.** Provider down > `LLM_OUTAGE_PAUSE_S` (60 s): agents disconnect, logins held, lives alive during the outage get `validForStudy: false`; auto-resume.
- **2026-11-17 · Starting setup mechanics.** The stock server alternates Eve/baby for quick logins (cooldown + baby ratios), so `INITIAL_EVES` come from a one-at-a-time burst; joins wait for "family room" so the ratio rule doesn't create extra Eves. Not guaranteed with leftover characters in the world.
- **2026-11-17 · Several worlds: independent server+agents pairs** (`deploy/WORLDS.md`), distinct `RUN_ID`/`LOG_DIR` per world.
- **2026-11-17 · Actions lists, human-UI equivalent (`ACTION_LIST_MAX=3`).** A reply may chain up to 3 actions, stopping at the first failure or salient event. Without it the fire chain's 10 s decay windows were unreachable at an ~8 s cycle; live, 3 steps light a fire at TIME_SCALE 1 with ~8 s replies and at 1.5 with ~11 s replies (TIME_SCALE 1 at ~11 s needs 4). LLM calls stay unpipelined; instead the action is checked against what the model saw (stale targets are skipped and explained). *Revisit:* if models abuse lists to script long routines (they can't exceed 3 steps), or if 4 is needed at TIME_SCALE 1.
- **2026-11-17 · Per-person flowers.** Siblings looked identical (same lineage hairstyle and face, similar inherited hair colour), so neither viewers nor agents could tell individuals apart. Every life now wears a flower in its hair: 8 shapes x 7 colours (56 variants), the palette kept away from the hair-colour space so a flower never reads as a personality colour. The agents service is the one authority: it assigns the flower at birth (`lives.ts`, `pickFlower`), unique among the living members of the lineage, stable for life, stored on the LifeRecord; old records get one on load. The viewer only draws `record.flower`. Visible to agents too (own flower in YOU, each nearby person's in PEOPLE, one line in the system prompt). Declared intervention (README).
- **2026-11-17 · Generated flower art.** The three hand-drawn canvas flowers (daisy, tulip, bellflower) looked out of place next to the real OHOL sprites. Replaced by AI-generated sprites in the OHOL style (gpt-5.4-image-2 via OpenRouter, white petals tinted at runtime like the real ones): daisy, tulip, poppy, iris, lily, forget-me-not. Catalogue now 11 shapes x 7 colours (77 variants). Stored records keep working: `daisy` and `tulip` kept their ids, the retired `bell` maps to `lily` (`LEGACY_FLOWER_SHAPES`), migrated on load and in the viewer. Sunflower left out (its dark seed disc tints badly).
- **2026-11-17 · The world survives agents restarts and code updates.** In continuous mode the run id is persisted (`LOG_DIR/research/current-run.json`) and reused on restart, so the agents log back into their living characters; a reconnect is not a birth and the life stays valid. A game-server restart (full deploy, machine restart) still starts a fresh run, because stock OHOL ends every living character then (`RESUME_ACROSS_SERVER_RESTART=1` if a save patch changes that). `deploy/start.sh` restarts only the agents service when it dies (backoff; a crash-looping hot-update override is dropped, back to the image's code; on the image it retries every 5 min instead of killing the world); only a game-server death restarts the machine. Hot updates (`deploy/hot-update.sh`) install agents + viewer code into `/data/app/versions/<v>` with an atomic `current` link and restart the agents only. An override belongs to the image it was installed on (`IMAGE_STAMP`): after a full deploy, start.sh ignores and unlinks it, so a deploy always runs its own code and an old override can't shadow newer image code. *Revisit:* if the game-save patch lands (then resume across server restarts), or if dependency changes become frequent (hot updates refuse a changed `package-lock.json`).
- **2026-11-17 · Reasoning is required.** Non-thinking models aren't interesting for this study. Baseline: self-hosted Qwen3-32B with mild reasoning (~300 thinking tokens); stretch goal: Qwen3.8-27B with mild reasoning. Expect 2–3 GPUs unless optimisation (speculative decoding, quantisation, engine, caching) brings it down.
- **2026-11-16 · `ACTION_LIST_MAX=4` by default** (was 3). The tech-tree audit (`docs/research/techtree-audit.md`, traps 1 and 11): the ember chain (drill on shaft, swap for leaf, leaf on ember shaft, ember leaf on tinder) and the hot-iron steps are 4 clicks inside a 10 s window, which a human does in ~3 s. Still human-UI equivalent.
